# GOG PARTNER NETWORK — ระบบเครือข่ายผู้ให้บริการคนไทยในอังกฤษ

เอกสารออกแบบระบบ "แพลตฟอร์มประสานการท่องเที่ยว" ที่ให้คนไทยในอังกฤษลงทะเบียนเป็นผู้ให้บริการ
(คนขับรถ · ตากล้อง · ไกด์ท้องถิ่น · ที่พัก · ร้านอาหารไทย) แล้วระบบจับคู่กับแฟนบอลไทยที่บินไปดูพรีเมียร์ลีก

---

## 0. สิ่งที่ต้องรู้ก่อนเปิดระบบ (อ่านก่อนเขียนโค้ดบรรทัดแรก)

ส่วนนี้ไม่ใช่การห้าม แต่เป็นความเสี่ยงที่ต้องออกแบบให้รัดกุมตั้งแต่ต้น ไม่งั้นแก้ทีหลังแพงมาก

### 0.1 การรับส่งผู้โดยสารโดยได้เงิน = งานที่ต้องมีใบอนุญาตในอังกฤษ

นี่คือประเด็นใหญ่ที่สุดของไอเดีย "คนไทยเอา Benz 7 ที่นั่งมาขับรับนักท่องเที่ยว"

- รถที่รับผู้โดยสารแลกกับค่าตอบแทนในอังกฤษต้องเป็น **Private Hire Vehicle (PHV)** ที่มีใบอนุญาต
  ทั้ง **ตัวรถ** **ตัวคนขับ** และ **ผู้จัดหางาน (operator)** — ออกโดยสภาท้องถิ่น (ลอนดอนคือ TfL,
  แมนเชสเตอร์คือ Manchester City Council หรือสภาเขตที่คนขับสังกัด)
- ประกันรถส่วนบุคคลทั่วไป **ไม่ครอบคลุม** การรับจ้าง ต้องเป็นกรมธรรม์ **hire and reward**
- **ถ้า GOG เป็นคนจับคู่ผู้โดยสารกับคนขับและรับเงิน GOG อาจเข้าข่ายเป็น operator เอง**
  ซึ่งต้องมีใบอนุญาต operator ของสภาท้องถิ่นนั้น ๆ

**ทางเลือกในการออกแบบ (เลือกอย่างใดอย่างหนึ่งก่อนเปิดรับจริง)**

| ทางเลือก | ความหมาย | ความเสี่ยง |
|---|---|---|
| A. GOG เป็นแค่ไดเรกทอรี | แสดงรายชื่อผู้ให้บริการ ผู้เดินทางติดต่อ/จ่ายเงินกันเอง GOG ไม่รับเงินค่าเดินทาง | ต่ำสุด · เริ่มได้เร็ว |
| B. GOG เป็น operator เต็มตัว | รับจอง รับเงิน จ่ายคนขับ | ต้องขอใบอนุญาต operator + ประกัน + ระบบร้องเรียนตามกฎหมาย |
| C. จับมือกับ operator ที่มีใบอนุญาตอยู่แล้ว | GOG ส่งงานให้บริษัทที่มีใบอนุญาต | กลางทาง · เริ่มได้เร็วและถูกกฎหมาย |

**ข้อเสนอ: เริ่มที่ A แล้วขยับไป C** และบังคับอัปโหลดใบอนุญาตตั้งแต่วันแรก
เพื่อให้ข้อมูลพร้อมเมื่อจะขยับไป B/C ภายหลัง

### 0.2 บริการอื่น ๆ

| ประเภท | สิ่งที่ต้องตรวจ |
|---|---|
| ที่พัก | กฎการปล่อยเช่าระยะสั้น (ลอนดอนจำกัด 90 วัน/ปี) · ความปลอดภัยอัคคีภัย · ประกัน |
| ร้านอาหาร | จดทะเบียนกับหน่วยงานอาหารท้องถิ่น · คะแนน Food Hygiene Rating |
| ไกด์ | อังกฤษไม่บังคับใบอนุญาตไกด์ทั่วไป แต่บางสถานที่รับเฉพาะไกด์ที่ได้รับการรับรอง (Blue Badge) |
| ตากล้อง | ถ่ายเชิงพาณิชย์ในบางสถานที่ต้องขออนุญาต · ประกันความรับผิดต่อบุคคลที่สาม |
| ทุกประเภท | สิทธิในการทำงานในสหราชอาณาจักร |

### 0.3 ข้อมูลส่วนบุคคลและการเงิน

- เอกสารยืนยันตัวตน (พาสปอร์ต ใบขับขี่ ใบอนุญาต) เป็นข้อมูลอ่อนไหวภายใต้ UK GDPR
  → เก็บใน storage แยก เข้ารหัส กำหนดอายุการเก็บ และเข้าถึงได้เฉพาะผู้ตรวจสอบ
- **อย่าเก็บไฟล์เอกสารไว้ใน D1** ให้เก็บใน R2 แล้วเก็บแค่ key + สถานะการตรวจใน D1
- ถ้าจะรับเงินแล้วจ่ายต่อให้พาร์ตเนอร์ ให้ใช้ **Stripe Connect** ซึ่งจัดการ KYC/AML/ภาษีให้
  อย่าสร้างระบบถือเงินเอง

## 1. โครงสร้างข้อมูล

```
partners                    โปรไฟล์ผู้ให้บริการ (1 คนมีได้หลายบริการ)
├── partner_services        บริการที่ขาย + ราคา + พื้นที่ให้บริการ
├── partner_vehicles        เฉพาะคนขับรถ — รุ่นรถ จำนวนที่นั่ง ทะเบียน
├── partner_documents       เอกสาร + สถานะตรวจสอบ + วันหมดอายุ
├── partner_availability    ช่วงเวลาที่ว่าง/ไม่ว่าง
└── partner_reviews         รีวิวจากผู้เดินทางที่ใช้บริการจริงเท่านั้น

booking_requests            คำขอจากผู้เดินทาง -> พาร์ตเนอร์
```

### partners

| ฟิลด์ | ชนิด | หมายเหตุ |
|---|---|---|
| `id` | TEXT PK | `ptn_` + สุ่ม |
| `kind` | TEXT | `driver` `photographer` `guide` `stay` `restaurant` |
| `display_name` | TEXT | ชื่อที่แสดงต่อผู้เดินทาง |
| `legal_name` | TEXT | ชื่อตามเอกสาร (ไม่แสดงสาธารณะ) |
| `city` | TEXT | `London` `Manchester` `Liverpool` … |
| `areas_json` | TEXT | พื้นที่ที่ไปได้ |
| `languages_json` | TEXT | `["th","en"]` |
| `email` `phone` `line_id` | TEXT | ช่องทางติดต่อ (ไม่แสดงจนกว่าจะจับคู่สำเร็จ) |
| `bio` | TEXT | แนะนำตัว |
| `status` | TEXT | `pending` `verified` `suspended` `rejected` |
| `verified_at` `verified_by` | TEXT | ใครอนุมัติ เมื่อไหร่ |
| `rating` `review_count` | REAL/INT | คำนวณจาก partner_reviews |

**สถานะเริ่มต้นคือ `pending` เสมอ** และหน้าเว็บสาธารณะแสดงเฉพาะ `verified`

### partner_services

| ฟิลด์ | หมายเหตุ |
|---|---|
| `id` `partner_id` | |
| `title` | เช่น "รับส่งสนามบิน MAN → ใจกลางเมือง" |
| `pricing_model` | `per_day` `per_hour` `per_transfer` `per_person` `per_night` |
| `price_thb` / `price_gbp` | เก็บสองสกุลไปเลย ไม่ต้องแปลงตอนแสดง |
| `capacity` | จำนวนคน/ที่นั่งสูงสุด |
| `matchday_ready` | true = รับงานวันแข่ง (รถติด คิวยาว ต้องคิดเวลาเผื่อ) |
| `notes` | เงื่อนไข เช่น ขั้นต่ำกี่ชั่วโมง |

### partner_vehicles (เฉพาะ `kind = driver`)

`make` `model` `year` `seats` `luggage_capacity` `plate` `has_child_seat`
`insurance_expires_at` `phv_licence_expires_at`

### partner_documents

`kind` = `passport` `driving_licence` `phv_driver_licence` `phv_vehicle_licence`
`hire_reward_insurance` `dbs_check` `food_hygiene` `business_registration` `right_to_work`
พร้อม `r2_key` `status` (`pending`/`approved`/`rejected`) `expires_at` `reviewed_by` `note`

> **กติกา:** พาร์ตเนอร์ประเภท `driver` จะขึ้นสถานะ `verified` ไม่ได้
> ถ้าเอกสาร `phv_driver_licence` `phv_vehicle_licence` `hire_reward_insurance`
> ยังไม่ `approved` หรือหมดอายุแล้ว — ตรวจที่ระดับ service ไม่ใช่แค่ UI

### booking_requests

`trip_id` (อ้างถึงทริปที่บันทึกไว้) `partner_id` `service_id` `date` `pax`
`status`: `requested` → `accepted` / `declined` → `confirmed` → `completed` / `cancelled`
`message` `contact_released_at` (ปล่อยเบอร์ติดต่อเมื่อสถานะ `accepted` เท่านั้น)

## 2. เส้นทางผู้ใช้

### ฝั่งพาร์ตเนอร์
```
สมัคร → กรอกโปรไฟล์ + บริการ → อัปโหลดเอกสาร → รอตรวจ (pending)
      → ทีมงานตรวจ → verified → รับคำขอจอง → ตอบรับ/ปฏิเสธ → ให้บริการ → รับรีวิว
```

### ฝั่งผู้เดินทาง
```
วางแผนทริป → ระบบเสนอพาร์ตเนอร์ที่ตรงกับเมือง/วันที่/จำนวนคน
           → ส่งคำขอ → พาร์ตเนอร์ตอบรับ → เห็นช่องทางติดต่อ → ตกลงกันเอง (เฟส A)
```

## 3. ตรรกะการจับคู่

คะแนนแนะนำ (ปรับน้ำหนักได้ภายหลัง — เก็บเป็นค่าคงที่ที่เดียวใน service)

| ปัจจัย | น้ำหนัก | เหตุผล |
|---|---|---|
| ตรงเมือง/พื้นที่ | 30% | อยู่คนละเมือง = ใช้ไม่ได้เลย |
| ว่างตรงวัน | 25% | โดยเฉพาะวันแข่งซึ่งทุกคนจองเต็ม |
| รองรับจำนวนคน | 15% | 7 ที่นั่งสำหรับ 6 คนพร้อมกระเป๋า |
| คะแนนรีวิว | 15% | |
| พร้อมงานวันแข่ง | 10% | ต้องรู้เส้นทางเลี่ยงรถติดรอบสนาม |
| ราคาเทียบระดับงบ | 5% | |

**ตัวกรองแข็ง (ไม่ผ่าน = ไม่แสดงเลย):** สถานะ `verified` · เอกสารไม่หมดอายุ · ไม่ถูกจองซ้อน

## 4. API ภายนอกที่ทำให้ระบบ advance ขึ้นจริง

เลือกเฉพาะตัวที่ **มีชั้นใช้ฟรีจริง** และเหมาะกับ Cloudflare Workers

### แผนที่ · สถานที่ · เส้นทาง
| บริการ | ใช้ทำอะไร | เงื่อนไข |
|---|---|---|
| **OpenStreetMap + Leaflet** | แผนที่พื้นฐาน (โปรเจกต์นี้ใช้อยู่แล้วในหน้าแผนที่สนาม) | ฟรี ไม่ต้องใช้คีย์ |
| **Overpass API** | ดึง POI จริงรอบโรงแรม/สนาม — ร้านอาหาร คาเฟ่ สถานีรถไฟ | ฟรี · ควรแคชผลไว้ อย่ายิงถี่ |
| **Nominatim** | แปลงชื่อสถานที่เป็นพิกัด | ฟรี · จำกัด 1 req/วินาที ต้องใส่ User-Agent ที่ระบุตัวตน |
| **OpenRouteService** | เส้นทาง เวลาเดินทางจริง isochrone "ภายใน 30 นาทีไปถึงไหนได้บ้าง" | ฟรีมีคีย์ · โควตาต่อวัน |
| **MapLibre + Protomaps** | ถ้าอยากได้แผนที่เวกเตอร์สวยและโฮสต์เอง | ฟรี/โอเพนซอร์ส |

### รูปภาพสวย ๆ
| บริการ | จุดเด่น | ข้อควรระวัง |
|---|---|---|
| **Wikimedia Commons API** | รูปสนาม/แลนด์มาร์กที่ลิขสิทธิ์ชัดเจน | **ต้องใส่เครดิตผู้ถ่ายและใบอนุญาตทุกภาพ** |
| **Wikipedia REST API** | รูปหลัก + คำอธิบายสั้นของสถานที่ | ฟรี |
| **Unsplash / Pexels API** | ภาพสวยระดับโฆษณา | ฟรีมีคีย์ · Unsplash ต้องใส่เครดิตและ trigger download event |

> อย่าดึงรูปจาก Google Images หรือเว็บข่าวมาใช้ตรง ๆ — ละเมิดลิขสิทธิ์แน่นอน

### ฟุตบอล
| บริการ | ใช้ทำอะไร |
|---|---|
| **football-data.org** | โปรแกรมแข่ง/ผลพรีเมียร์ลีก ชั้นฟรีพอสำหรับลีกเดียว |
| **TheSportsDB** | โลโก้สโมสร รูปสนาม ฟรี |
| **openfootball (GitHub)** | ชุดข้อมูลโปรแกรมแข่งแบบไฟล์ ไม่ต้องพึ่ง API |

### เดินทาง
| บริการ | ใช้ทำอะไร | เงื่อนไข |
|---|---|---|
| **Amadeus Self-Service** | ค้นหาไฟลต์และโรงแรมของจริง | มี test environment ฟรี · ขึ้น production ต้องสมัคร |
| **TfL Unified API** | รถไฟใต้ดิน/รถเมล์ลอนดอน สถานะสายจริง | ฟรี |
| **Open-Meteo** | พยากรณ์อากาศวันแข่ง | **ฟรีสนิท ไม่ต้องใช้คีย์** เหมาะกับ Workers มาก |
| **Frankfurter / exchangerate.host** | เรตแลกเงิน ฿/£ | ฟรี |
| **Ticketmaster Discovery** | อีเวนต์/คอนเสิร์ตช่วงที่ไปเที่ยว | ฟรีมีคีย์ |

### จอง/ชำระเงิน (เมื่อขยับไปเฟส B/C)
- **Stripe Connect** — จ่ายเงินให้พาร์ตเนอร์ พร้อม KYC/AML ในตัว
- **Duffel** — API จองตั๋วเครื่องบินจริง
- **Booking.com Demand API / Expedia Rapid** — ต้องผ่านการอนุมัติเป็นพาร์ตเนอร์
- รถเช่า: ส่วนใหญ่เป็นโปรแกรม affiliate ไม่มี API ฟรีสำหรับจองจริง

**ลำดับที่แนะนำให้ต่อ:** Open-Meteo → Wikimedia → Overpass/Nominatim → Ticketmaster →
football-data.org → Amadeus (test) → Stripe Connect

## 5. สถาปัตยกรรม

```
app/
  partner-register.tsx     ฟอร์มสมัครเป็นพาร์ตเนอร์
  partner-directory.tsx    รายชื่อพาร์ตเนอร์ที่ผ่านการตรวจแล้ว
  trip-planner.tsx         แทรกบล็อก "พาร์ตเนอร์ไทยในเมืองนี้"

services/
  partners/                ตรรกะจับคู่ + กติกาเอกสาร (ไม่มี JSX)
  maps/                    อะแดปเตอร์ Overpass/Nominatim + แคช
  images/                  อะแดปเตอร์ Wikimedia/Unsplash + เครดิตภาพ
  weather/                 Open-Meteo

lib/server/
  partners.ts              CRUD + เปลี่ยนสถานะ + ตรวจเอกสาร
  api.ts                   /api/partners, /api/partners/:id, /api/bookings
```

**กติกาเดิมยังใช้:** ตรรกะทั้งหมดอยู่ใน `services/` UI แค่เอาไปวาด
และ `lib/server/` เป็นชั้นที่แตะฐานข้อมูล

## 6. ลำดับการทำ

| เฟส | ได้อะไร |
|---|---|
| **P1** | ตาราง `partners` + `partner_services` + API สมัคร + ฟอร์มสมัคร (สถานะ `pending` ทั้งหมด) |
| **P2** | ไดเรกทอรีสาธารณะ + ตรรกะจับคู่ + แทรกบล็อกพาร์ตเนอร์ในหน้าวางแผนทริป |

| **P4** | คำขอจอง + ปล่อยช่องทางติดต่อเมื่อตอบรับ + รีวิวหลังใช้บริการ |

| **P6** | ต่อ Amadeus (ไฟลต์/โรงแรมจริง) และ Stripe Connect ถ้าตัดสินใจไปเฟส B/C |
